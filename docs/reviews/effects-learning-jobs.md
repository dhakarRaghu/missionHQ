## 2. The reader and a per-concept tap

Bundle: `frontend/public/reader/index.json` + `lessons/*.html`, fetched by `frontend/src/lib/reader.ts:45-70` with `cache: "no-store"`; list `frontend/src/app/read/page.tsx`; page `frontend/src/app/read/[slug]/page.tsx` renders `srcDoc` in `sandbox="allow-scripts allow-popups allow-popups-to-escape-sandbox"` (no same-origin). `harden_page` (`api/learning.py:43-70`) injects CSP `default-src 'none'; style-src 'unsafe-inline'; script-src 'unsafe-inline'; img-src data:; font-src data:; form-action 'none'; base-uri 'none'` (`:33-36`) and `<base target="_blank">`. Gate: `frontend/src/proxy.ts` Basic-auth on `READER_PASSWORD`, redirects console routes to `/read` when `VERCEL && !NEXT_PUBLIC_API_BASE`; `providers.tsx:21,45,73` exempts `/read` from the auth guard and event stream.

Two hard constraints for a tap:
1. Inside the lesson document, `connect-src` inherits `default-src 'none'`, so `fetch`/`XHR` from the page is blocked by its own CSP, and the sandboxed frame has an opaque origin, so `localStorage` throws. The tap must be a `window.parent.postMessage({concept:'c1', verdict:'got_it'})` from the kit script (new code in `lesson_kit.py` `KIT_JS`, triggered per `<h2 data-concept>`/`<ol class="concepts"> li`) received by `read/[slug]/page.tsx`, which validates `event.source === iframe.contentWindow` and the message shape (the page is model-written markup: treat the message as data, whitelist `c\d+` and two verdict strings).
2. Where the outer page sends it:
   - **POST to the backend over Tailscale.** Needs the phone on the tailnet, `CORS_ORIGINS` = the Vercel origin (`app.py:91-100`, `allow_credentials=False`) and auth: the `Tailscale-User-Login` header is only added by Serve on the tailnet path (`deps.py:29-32`) — a cross-origin fetch from the Vercel page to `https://<mac>.ts.net` would carry it only if the phone is on the tailnet; otherwise you'd need the bearer token in the Vercel page, which breaks the "the reader calls no API / less leaves this machine" rule in `docs/deploy.md` §12 and puts `API_BEARER_TOKEN` in a public deployment. Also fails silently when the Mac is asleep, the exact case `/read` exists for. Trifecta: fine (owner-originated write, no agent); privacy: the tap payload is only `{lesson, concept, verdict}`.
   - **Vercel KV.** Needs a Vercel serverless route behind `proxy.ts` (the gate has no matcher, so it covers `/api/tap` too), a KV binding, and a pull step on the Mac (the nightly export could `GET` the KV through the same Basic auth and write `hq.concept_signals`). Adds a second store and a second secret, and the "no backend" deployment becomes a stateful one. Privacy: only tap tuples leave the machine.
   - **Defer: store on the phone, carry back at export time.** `localStorage` on the *outer* `/read` origin (allowed; only the iframe is opaque) keyed by file+concept; export the pending taps as a small JSON the owner pastes/uploads once, or — simpler — the console has the same tap UI in `LessonPageFrame` (`frontend/src/components/features/learn/lesson-frame.tsx`) writing straight to the backend. The phone shows taps locally and the laptop records them. Zero new secrets, zero new infra, but the "next outline reads the taps" loop only closes when he taps on the laptop or syncs.
   Assessment: option 3 first (it is what `docs/deploy.md` §12 "What the phone cannot do" already promises), with a tiny authenticated POST as the upgrade if he is always on the tailnet. Either way the backend needs a table `hq.concept_signals(lesson_id, concept, verdict, at, via)` and an endpoint under `/learning`, and the outline stage reads it for the course.

Safer alternatives: (a) keep the nightly `build()` but commit/push only when the lesson set changed (hash the page list, drop `built_at` from the diff), on a dedicated branch (`reader`) that Vercel deploys from, so `main` is never touched and conflicts with his work are impossible; (b) put `frontend/public/reader` in its own tiny repo (like the vault) and let `ops/backup.sh` push it beside the vault; (c) skip git entirely: `vercel deploy --prebuilt` of the static folder from the backup script. (a) is the smallest change consistent with "vault commits once a day".
