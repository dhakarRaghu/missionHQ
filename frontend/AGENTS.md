# Mission HQ console: design rules

1. **Structure.** Routes live in `src/app/(console)/<view>/page.tsx`. Shared UI in `src/components/ui` (shadcn, do not hand-edit styles). Feature components in `src/components/features/<view>`. API client and types in `src/lib/api` (`client.ts`, `types.ts`). Hooks in `src/hooks`.
2. **No hard-coded CSS.** Colours, fonts and radii are CSS variables in `src/app/globals.css`, mapped in `@theme inline`. Components use Tailwind utilities and shadcn variants only. No palette classes such as `bg-amber-500`, no inline `style` for layout or colour.
3. **Rewrites, not CORS.** The browser calls the relative `/api/*` path. `next.config.ts` rewrites it to `BACKEND_ORIGIN` (server-only env var). `compress` is off so SSE frames pass through `next start`.
4. **TanStack Query plus one SSE stream.** Server data is read with `useQuery` and keys from `qk` in `client.ts`. One `EventSource` (`src/lib/sse.ts`, started from `providers.tsx`) writes the feed and connection status into the query cache and invalidates the keys each event affects. Polling is a fallback only while the stream is not connected.
5. **Thirteen views.** Home, Board, Jobs, Ideas, Radar, Learn, Courses, Chat, Memory (`/vault`), Runs, Agents, Tools, Settings. Radar (2026-09-28) shows where project ideas come from: the counts from collection to proposal, the project he is building, the ideas that passed the gate with the quotes behind them, and the open problems. Every action on it answers with the whole page (`/api/radar`), which is written into the query cache. Learn (2026-09-12) shows tutor's daily lesson; its HTML page is generated by a model from web-derived digests, so it renders in an iframe with `sandbox="allow-scripts allow-popups allow-popups-to-escape-sandbox"` and NO same-origin, fetched as text through `/api/learning/page`, which injects both a Content-Security-Policy meta and `<base target="_blank">`. Never render that markup in this origin, and never give the frame `allow-same-origin`: the console holds the token that can start agents. The popup flags and the `<base>` are a pair and must stay together — the lesson links to its sources, those links carry no `target`, and on 2026-09-12 clicking one navigated the frame itself to the live site, which looked from the outside as though the console had downloaded an entire website into the app. Strip either half and that returns. `/learn-full?path=…` (outside the `(console)` group, so it keeps the root layout's providers and loses the shell) opens one lesson in its own tab at full viewport, with the identical sandbox flags. Never reach for the shortcut of pointing a tab at a `blob:` or `data:` URL built from the HTML: a blob URL inherits THIS origin, which would hand model-generated markup the console's token and storage — the precise thing the frame exists to prevent. The lesson is the whole view: it takes the full width and height, while the day picker and the "what do you want to learn" box collapse into slim drawers rather than taking a pane, and the sources are not repeated here because the page already ends with them. Two were folded in on 2026-09-10 at the owner's request: the Inbox is the top of Home (the pending tickets sit where a count-and-link card used to point at them), and the Live feed is a tab on Runs (`?tab=feed`), since a run and its events are one story at two resolutions. `/inbox` and `/feed` remain as redirects. Every list branches on loading, error (with Retry) and empty state, in that order, and an empty state is a title, one sentence about what will appear, and a CTA where there is somewhere to go. **No page prints its own title.** The shell's top bar already names the current view, so a page-level heading duplicates it and costs vertical space that a 13-inch screen does not have. A detail view identifies its record inside its own content instead.
6. **One page-level scrollbar, in one of two shapes.** `ConsoleShell` is exactly one viewport tall. A normal page uses a `min-h-full` wrapper inside a scrolling container, so its bottom padding sits under the last row. A full-height view (Chat, Memory — listed in `FULL_HEIGHT`) uses an `h-full` wrapper inside a non-scrolling container and scrolls its own panes with `.pane-scroll`. The height must be definite, not a minimum: with `min-h-full` the flex basis stays indefinite, panes grow to their content, and the page header is pushed off screen.
7. **Layout primitives live in CSS.** Two-pane views use `.console-split` plus `.pane-narrow` or `.pane-wide` from `globals.css`, not arbitrary Tailwind grid templates. An arbitrary template such as `md:grid-cols-[18rem_minmax(0,1fr)]` silently failed to compile once and collapsed the Vault into one column.
8. **Time formatting.** Lists show relative time from `lib/time.ts` (`timeAgo`) with the exact value in a `title`. Detail views show the full timestamp.
